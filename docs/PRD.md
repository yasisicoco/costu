# costu 서비스 기획 및 누적 요구사항

상태: Cloud/Linux MVP 검증 및 기능 개선 진행. 사용자가 선택한 얼굴 비공개 카메라 아바타 연동을 구현 중이다. 최초 작성 2026-11-04 KST.

이 문서는 PM 추천안과 구현 기본값이다. 실제 고객 검증 결과나 사용자가 직접 승인한 사업 의사결정으로 간주하지 않는다. 개발은 이 주 개발 채팅의 Codex Cloud 환경에서 진행한다. Cloud 전환은 앱 호스팅을 뜻하지 않는다.

## STEP 1. 서비스 정의

**한 줄 소개:** 얼굴을 공개하지 않고 친구와 가볍게 연결되어, 각자의 속도로 집중하는 작은 서재.

문제는 공부 의지의 부족보다 함께 시작할 때 필요한 예약·카메라·대화의 부담이다. 초대 링크로 들어와 아바타의 상태와 응원으로 연결된다. 카메라 없이 바로 사용할 수 있으며, 사용자가 원하면 기기에서 처리한 고개 움직임과 표정을 아바타에 반영한다. 얼굴 영상은 서재에 공유하지 않는다. 혼자 있을 때도 같은 타이머와 기록을 사용하므로 초기 사용자 부족에 대응한다.

비전은 감시나 순위 경쟁 없이 꾸준히 돌아오는 집중 공간이다. 가치 제안은 빠른 시작, 부담 없는 동행, 자기 속도의 성취감이다. 집중력 향상 효과는 아직 입증하지 않았다.

### 경쟁 비교와 한계

| Focusmate | 파트너와 카메라를 활용하는 집중 세션 | 예약과 얼굴 공개 부담을 줄였을 때 시작이 쉬워지는가 |
| StudyStream | 영상 기반 Focus Rooms와 상태·아바타 등의 기능 | 아는 친구 중심의 작은 초대형 공간이 더 편안한가 |

아바타·공부방·타이머 각각은 독점적 차별점이 아니다. StudyStream의 비영상 이용 가능성도 있으므로 모든 경쟁 서비스가 카메라를 강제한다고 주장하지 않는다. 차별성은 기능 조합과 시작 경험으로 검증한다.

## STEP 2. 사용자 분석

초기 모집은 성인 대학생·자격시험 준비생으로 좁힌다. 미성년자·불특정 공개 커뮤니티 운영 정책은 별도 설계가 필요하므로 첫 모집에서 제외하는 PM 기본안이다.

| 페르소나 가설 | Pain Point | 사용 시나리오 |
|---|---|---|
| 자격시험 준비생, 26세 | 친구와 시간을 맞추고 영상 준비하기 번거롭다 | 혼자 25분 시작 → 링크 공유 → 친구가 중간 합류 |
| 대학생, 22세 | 집에서 혼자 시작하기 어렵고 낯선 사람과 대화가 부담스럽다 | 친구가 보낸 링크 → 아바타로 입장 → 각자 공부 |

사용자 여정은 앱 열기 → 바로 타이머 시작 → 필요하면 친구 초대 → 조용한 상태 공유 → 종료 기록 → 다음 집중이다. 가입과 온보딩을 선행 조건으로 두지 않는다.

검증이 필요한 가정: 아바타 상태와 선택형 움직임 연동으로 존재감이 생기는지, 실제 친구를 초대하는지, 개인 타이머만으로 재방문하는지, 카메라 연동의 기기 부담과 동의 흐름을 받아들이는지.

혼자와 함께의 타이머는 같다. 서재 입장 시 진행 중 타이머를 초기화하지 않는다. 방에서 나와도 개인 공부를 계속할 수 있다. 1–120분의 시간을 선택하고, 25분을 기본으로 한다. 집중을 완료하거나 1초 이상 기록하고 마치면 5분 휴식을 제안한다. 사용자가 선택해야 휴식이 시작되며 건너뛰거나 다음 집중을 바로 시작할 수 있다. 휴식도 일시 정지·재개·조기 종료·새로고침 복원을 지원한다. 휴식은 공부 기록·목표·통계에서 제외하고, 종료 후 이전 집중 길이로 대기하며 다음 공부를 자동 시작하지 않는다.

### 기능 개선: 공부할 일과 집중 기록 연결

현재는 세션마다 주제를 입력하고 타이머를 고르지만, 그 기록이 다음에 할 공부로 이어지지 않는다. 이번 기능은 공부할 일을 저장해 두고 한 번의 선택으로 집중을 시작하며 실제 기록으로 목표 진행률을 확인하게 한다. 친구와 같은 서재에 있더라도 각자의 공부할 일은 개인 정보로 유지한다. 목록은 ‘공부할 일’로 부르며 날짜가 바뀌어도 미완료 항목을 지우지 않는다.

사용 흐름은 공부할 일에 제목과 목표 분량 입력 → 목록에서 집중 시작 → 일시 정지 또는 종료 기록 → 누적 진행률 확인 → 남은 공부 이어 하기다. 할 일을 만들지 않아도 기존 자유 집중을 바로 시작할 수 있다.

| 항목 | 구현 기준 |
|---|---|
| 추가 | 제목 1–50자, 목표 분량 1–120분. 빈 제목과 범위 밖 분량은 저장하지 않음 |
| 집중 시작 | 대기 중에만 선택 가능. 제목과 남은 목표 분량을 타이머에 적용해 시작하며 진행 중 집중·일시 정지·휴식을 덮어쓰지 않음 |
| 진행률 | 같은 taskId를 가진 저장된 집중 기록의 실제 초 합계로 계산. 같은 제목의 다른 할 일은 별도로 집계 |
| 조기 종료 | 실제로 기록한 시간만 누적하고 다음 선택 시 남은 분량을 제안. 남은 시간이 1분 미만이면 기존 타이머의 최소 단위인 1분 사용 |
| 완료 | 누적 시간이 목표에 도달하면 완료 표시. 초과 집중 시간도 실제 공부 기록에 남기며 진행률 표시는 100%로 제한 |
| 휴식 | 할 일의 진행률에 포함하지 않고 다음 공부를 자동 시작하지 않음 |
| 보관 | 새로고침·오프라인·여러 탭에서도 같은 Origin의 계획과 기록 사용. 날짜가 지나도 미완료 계획 유지 |
| 삭제 | 해당 할 일에 연결된 타이머가 진행·일시 정지 중이면 삭제할 수 없음. 그 외에는 할 일만 제거하며 이미 저장된 공부 기록과 당시 주제는 보존 |
| 백업 | 기존 기록 백업의 호환성을 유지하고 새 계획도 내보내기·복원 가능하게 함. 동일 id는 중복 생성하지 않음 |
| 공개 범위 | 제목·분량·진행률은 서버나 다른 서재 참가자에게 전송하지 않음 |

완료 판단은 빈 목록 안내, 추가·선택·집중·부분 기록·이어 하기·완료·삭제·복원 흐름의 실제 브라우저 검증이다. 기존 타이머 복원·서재·휴식·백업 회귀 테스트도 함께 통과해야 한다. 목록 순위 경쟁, 친구에게 과목 공개, 마감일·반복 일정, 자동 다음 과목 시작, 계정 기반 동기화는 이번 범위에서 제외한다.

### 사용자 승인 기능: 얼굴 비공개 카메라 아바타 연동

사용자는 얼굴을 보여 주는 화상방 대신 카메라에서 읽은 표정과 고개 움직임을 아바타에 반영하는 방식을 선택했다. 이 선택은 카메라를 필수로 쓰거나 얼굴 영상을 공유하는 승인이 아니다. 기능 기본값은 꺼짐이고, 새로고침·재방문·탭 복귀 때 자동으로 카메라를 켜지 않는다.

사용 흐름은 집중 공간에서 설명 확인 → 사용자가 ‘카메라로 아바타 움직이기’를 선택 → 브라우저 카메라 권한 허용 → 내 아바타의 연동 상태 확인 → 같은 서재에서는 아바타 움직임만 동기화 → 언제든 끄기다. 켜기 전에 ‘영상은 기기에서만 처리되며, 켜져 있는 동안 같은 서재에 고개·눈·입 움직임 수치가 전달된다’고 설명한다. 사용자 얼굴 영상은 화면 공유나 원격 참가자 미리보기로 표시하지 않는다.

| 항목 | 구현 계약 |
|---|---|
| 선택·권한 | 기본 꺼짐. 사용자가 켜기 버튼을 누를 때만 카메라 권한 요청. 카메라 미지원·권한 거부에도 기존 집중·기록·서재 사용 가능 |
| 기기 내 처리 | 영상 프레임과 얼굴 랜드마크는 기기 런타임에서 일시 처리하며 파일·브라우저 저장소·공부 기록·백업·서버에 저장하거나 전송하지 않음 |
| 공유 데이터 | 같은 서재에 있는 동안 정규화된 고개 방향(yaw/pitch/roll), 눈·입·미소 값만 전달. 영상·음성·얼굴 좌표 전체·얼굴 식별 정보는 전송하지 않음 |
| 공유 범위·보관 | 움직임은 현재 서재의 아바타 표현에만 사용. 서버에서 현재 동작을 저장하지 않고 임시 중계만 하며 영구 기록·분석 로그에 남기지 않고 퇴장·단절 시 상대방 아바타를 중립으로 전환 |
| 표현 한계 | 눈 깜빡임·입 움직임·고개 기울기를 표현하며 감정·기분·학습 진위·집중도·신원은 추론하지 않음. 미소 값은 얼굴 형태의 움직임 표현이지 감정 판정이 아님 |
| 타이머 독립 | 얼굴 인식 여부와 표정으로 타이머·공부 기록·자리 비움 상태를 자동 변경하지 않음 |
| 끄기·오류 | 끄기, 인식 초기화 오류, 권한 거부, 탭 백그라운드 전환, 장치 종료 시 스트림 트랙을 해제하고 아바타를 중립으로 되돌림. 뒤늦게 허용된 스트림도 끄기 의사가 있으면 즉시 해제 |
| 인식 실패 | 얼굴을 찾지 못하거나 동작 값이 오래되면 중립 아바타로 표시하고 타이머는 유지. 조명·안경·카메라 각도 등에 따라 표현이 부정확할 수 있음을 안내 |
| 배포 자산 | 추론 라이브러리·모델은 앱과 같은 Origin에서 제공. 앱 실행 중 외부 CDN에서 코드·모델을 내려받는 경로를 만들지 않음 |
| 권한 정책 | 카메라는 앱 자체 Origin에서만 사용하고 마이크는 계속 차단. 새 유료 자원이나 서비스 배포·접근 범위는 이 기능 승인에 포함하지 않음 |

검증은 순수 동작 변환·입력 검증, 같은 서재의 두 브라우저 동기화와 다른 서재 차단, 끄기·오류·권한 거부·백그라운드·장치 종료의 스트림 해제, 원본 영상·랜드마크의 네트워크 비전송, 기존 타이머 회귀를 포함한다. 생성 영상이나 가짜 카메라로 촬영한 자동 테스트 스냅샷은 ‘테스트용 카메라 입력’으로 구분하며 실제 사용자 표정 인식 품질의 증거로 제시하지 않는다. 실제 iOS Safari·Android Chrome의 인식 품질, 발열·배터리, 화면 잠금 후 복귀는 별도 실기기 검증 전까지 미검증으로 남긴다.

### 예외 및 데이터 기준

- 잘못된 코드·없는 방·만석·연결 실패: 명시적인 안내, 개인 타이머 유지.
- 카메라·마이크 부재: 기본 집중·기록·서재 사용에 영향 없음. 선택형 카메라 연동만 사용할 수 없으며 마이크는 요청하지 않음.
- 자리 비움: 타이머 일시 정지와 함께 상태 변경.
- 서버 단절: 개인 타이머·기기 기록은 유지하고 서재 상태가 마지막 연결 기준임을 표시. 방 복귀 확인 전 응원·상태·초대를 비활성화하고 재시도 제공. 30초 유예 후 자리가 제거될 수 있음.
- 단절 중 퇴장: 복귀해도 자동 재입장하지 않음. 일시 정지·휴식 상태는 복귀 시 자리 비움으로 반영.
- 새로고침: 타이머 복원, 세션별 재접속 토큰으로 서재 복귀 시도.
- OS가 브라우저를 정지: 연결 지속과 종료 알림 보장 없음. 복귀 시 실제 시각으로 타이머 보정. 카메라는 백그라운드에서 해제하며 돌아와도 자동으로 다시 켜지 않음.
- 저장소 사용 불가: 경고하고 내보내기 유도.
- 공부 시간은 학습의 진위나 집중도를 보증하는 지표가 아님.
- 자정을 넘긴 세션은 종료일에 기록. 함께 분류는 혼합 세션을 포함.

## STEP 4. UX/UI 설계

IA는 집중 공간 / 나의 기록 / 나의 설정 3개다. 온보딩·방 생성·방 참여는 독립 페이지 대신 가이드 또는 모달로 제공한다.

| 화면 | 구성 | 요구사항 |
|---|---|---|
| 집중 공간 | 모드 선택, 서재 일러스트, 타이머, 주제, 시간 설정, 목표, 공부할 일, 선택형 카메라 연동, 초대 공간 | 로그인·카메라 없이 시작, 할 일에서 집중 시작, 진행 중 주제·길이 변경 금지 |
| 실시간 서재 | 참가자 아바타, 선택형 움직임 동기화, 수동 상태, 초대 코드, 리액션, 나가기 | 허구 참가자·얼굴 영상 공유 금지, 방 외부에 상태·움직임 유출 금지 |
| 기록 | 오늘·전체 요약, 7일 차트, 세션 목록, 백업 | 빈 상태 안내, 중복 복원 방지 |
| 설정 | 아바타, 닉네임, 하루 목표, 프라이버시 안내 | 이름 최대 16자, 목표 15–720분 |

와이어프레임: 데스크톱은 왼쪽 메뉴 → 상단 인사 → 왼쪽 큰 집중 카드·오른쪽 목표 → 하단 서재. 모바일은 상단 제목 → 집중 카드 → 압축 목표 카드 → 서재 → 하단 메뉴 순서다.

스타일은 아이보리 바탕, 세이지 그린, 낮은 자극의 자체 SVG 일러스트를 사용한다. 아바타는 사용자가 선택한 캐릭터다. 선택형 카메라 연동에서는 얼굴 형태의 움직임만 반영하고 사용자의 실제 외모·감정·학습 여부를 판정하지 않는다. 응원은 짧게 나타나며 강제 음성·진동·알림을 쓰지 않는다. 동작 줄이기 설정을 존중하고 모달 포커스를 유지한다. 모바일 본문·조작 글자는 14px, 입력은 16px를 기준으로 하고 보조 정보는 12px 이상을 우선한다. 터치 영역은 최소 44×44 CSS px, 일반 텍스트 대비는 4.5:1 이상을 기준으로 검사한다.

## STEP 5. 기술 설계

현재 React + TypeScript + Vite, Node.js + Express + Socket.IO를 사용한다. 기획의 목적은 모바일 앱이며, 현재 산출물은 설치 가능성을 제공하는 웹 manifest와 오프라인 셸을 갖춘 반응형 웹 MVP다. 앱스토어 출시는 완료하지 않았다.

| 개발 방식 | 장점 | 부담 | 추천 시점 |
|---|---|---|---|
| 모바일 웹 | 빠른 UX 검증·링크 초대·공유 코드베이스 | 백그라운드·네이티브 감지 제약 | 현재 |
| React Native / Expo | 모바일 권한·네이티브 SDK 활용 | 스토어·기기별 빌드와 검증 | 검증 후 앱 배포 |
| Flutter | 일관된 렌더링 | Dart 전환 및 네이티브 연동 | 팀 역량에 맞을 때 |
| Swift / Kotlin 각각 | 세부 OS 기능 제어 | 1인 유지비가 큼 | 플랫폼별 필요가 확인될 때 |

카메라 접근 결정:

- 수동 상태 + 기본 아바타: 기본 경험으로 유지하며 카메라 없는 집중을 지원.
- 기기 내 얼굴 동작 추정 + 아바타 매핑: 사용자가 승인한 선택형 기능으로 구현. 원본 프레임·랜드마크를 전송하지 않고 정규화된 표현 값만 같은 서재에 전달. 모델 용량·추론 속도·기기 발열·배터리는 실기기 검증 필요.
- 카메라 기반 존재 감지·집중도 판정: 구현 범위에서 제외.
- 원격 실시간 영상 변환·얼굴 영상 공유: 구현 범위에서 제외.

음성은 추후 관리형 WebRTC/SFU를 우선 비교한다. P2P mesh는 참가자 수 증가에 따라 업로드와 연결 수가 증가한다. 가격과 실제 음성 이용량을 확인하기 전 제공업체를 확정하지 않는다.

현재 추가 유료 인프라를 생성하지 않았다. 미래 비용은 동시 접속 수·실시간 메시지 빈도·트래픽·로그 보관·음성 참가자 분량에 따라 산정한다. 월 예산 상한과 비용 발생은 사용자 판단을 받는다. 구체적인 월 비용·수용 인원은 실측 전 추정하지 않는다.

실시간·데이터 모델·보안 세부는 ARCHITECTURE.md에 유지한다.

## STEP 6. 개발 및 검증 계획

구현 순서는 개인 집중 → 기록 → 초대형 실시간 서재 → 예외·재접속 → 반응형·오프라인 → 브라우저 테스트다. 현재 이 흐름의 로컬 MVP가 작성됐다.

Cloud 환경 연결과 기존 테스트 재현을 완료했다. 다음은 실기기 검증, 소규모 비공개 테스트 순서다. 기간은 1인 기준 1–2주를 첫 외부 테스트 준비의 작업 가정으로 두며 실제 가능 시간·실기기·배포 환경에 따라 변경한다. 인증·음성·카메라까지 포함한 앱스토어 출시 일정을 이 범위에 넣지 않는다.

난이도: 타이머·기록 낮음~중간, 재접속·다중 탭 중간, 인증·데이터 동기화 중간~높음, 음성·카메라·모바일 백그라운드 높음.

로컬 완료와 외부 출시 기준을 분리한다. 로컬 완료는 타입 검사·빌드·서버 테스트·실제 브라우저 시나리오 통과다. 외부 테스트는 HTTPS·모바일 Safari/Chrome·로그/장애 처리·초대 공유·개인정보 안내·운영 창구 확인이 추가로 필요하다.

## STEP 7. 사업성 검토 및 실험

초기 시장 진입은 무작위 공개방이 아니라 기존 친구 2–4명 단위의 성인 스터디 그룹으로 시작한다. 초대 링크가 유입 경로이며 허구의 실시간 사용자나 항상 켜진 사람을 사용하지 않는다. 데이터 수집 SDK와 연락 발송은 아직 도입하지 않았다.

아래 수치는 시장 벤치마크가 아니라 첫 파일럿의 사전 판단 기준이다.

| 검증 가설 | 방법 | 처음 정한 판단 기준 |
|---|---|---|
| 쉽게 시작한다 | 5개 그룹에서 과업 관찰 | 안내 없이 60초 안에 함께 시작, 시도 80% 이상 성공 |
| 얼굴 없이 존재감을 느낀다 | 25분 후 1–5점 설문 | 중앙값 4점 이상, 부족한 정보 질적 수집 |
| 함께 경험이 다시 쓰게 만든다 | 같은 사람의 solo/together 경험 비교 | 2주 동안 2회 이상 함께 사용한 그룹 비율 50% 이상 |
| 혼자서도 가치가 있다 | 동료가 없을 때의 자발적 실행 관찰 | 자발적 사용 이유가 최소 3개 그룹에서 반복됨 |

표본은 방향성을 찾기 위한 것이며 통계적 인과관계를 입증하지 않는다. 선택형 카메라 연동의 사용 의향과 표정 표현 오차·기기 부담은 실제 사용 검증에서 별도로 확인한다.

리텐션은 타이머 종료 성취, 친구와의 가벼운 초대, 개인 기록 연속성으로 설계한다. 순위·강제 알림·연속 출석 상실 압박은 초기 제외한다.

수익화 후보는 아바타·서재 테마와 고급 개인 회고다. 기본 함께 공부 기능의 가치를 확인하기 전 결제·가격·유료 기능을 확정하지 않는다. 광고·영상 데이터 판매는 추천하지 않는다.

실패 가능성은 존재감 부족, 친구 초대의 부담, 개인 타이머 대체 불가, 앱 잠금 후 단절이다. 각각 최소한의 상태 신호 실험, 링크 흐름 간소화, 기본 타이머 품질 개선, 실제 모바일/네이티브 검증으로 대응한다. 카메라나 공개방을 무조건 추가하는 방식으로 해결하지 않는다.
