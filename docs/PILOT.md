# 실제 휴대폰 테스트 배포 제안

상태: 검토용 설정과 절차 준비. 서비스 생성·계정 연결·외부 배포는 아직 수행하지 않았다. 앱의 외부 공개 범위가 달라지므로 사용자 승인 후 진행한다.

## 현재 스냅샷

GitHub 초안 PR #1의 개발 브랜치 `feat/study-plan-and-focus-flow`에 기능을 전달했다. 공부할 일·남은 목표 이어 하기·기록 진행률·5분 휴식·친구 초대 공유·진행 중 타이머 복귀가 구현됐다. 단위·서버 17개와 브라우저 29개 시나리오를 검증했다. 실제 iOS Safari·Android Chrome·OS 화면 잠금·실제 공유 시트는 아직 검증하지 않았다.

## 선택지와 추천

| 선택지 | 외부 접근과 비용 | 진행할 수 있는 검증 |
|---|---|---|
| 추천: Render Free 임시 테스트 | 공개 HTTPS 앱 URL, 친구 2–4명에게만 전달. 유료 전환·결제수단 추가·DB·도메인 생성 없음 | 실제 휴대폰 두 대의 초대·공유·연결 복귀 |
| 기존 개인 Node 서버 사용 | 사용자가 가진 서버의 접근 정책·비용·HTTPS 설정을 먼저 확인 | 기존 환경에 맞춰 동일 시나리오 검증 |
| Cloud 내부 개발 계속 | 앱 외부 배포 없음 | 기능 개발·브라우저 자동 검증, 실제 타 기기 검증은 별도 |

추천안은 운영 출시가 아닌 짧은 기능 시험이다. 서비스 화면은 URL을 아는 사람이나 전달받은 제3자도 열 수 있다. 서재만 초대 코드로 구분되며 계정 인증·접근 차단 기능은 없다. 전체 앱이 비공개인 배포로 표현하지 않는다. 참가 대상은 성인 친구 2–4명이며 제3자에게 초대 링크를 전달하지 않도록 안내한다.

## 비용과 서비스 한계

[Render 무료 서비스 문서](https://render.com/docs/free)를 2026-11-10에 확인했다. 무료 인스턴스라도 기존 결제수단이 있으면 대역폭·빌드 한도 초과 시 과금될 수 있다. 따라서 계정 결제수단·사용량을 먼저 확인하고, 결제수단 없이 무료 한도에서 중단되는 조건을 확인할 수 있을 때만 진행한다. 기존 결제 설정을 임의로 바꾸지 않는다. 비용 0원을 보장할 수 없는 계정이면 배포 전에 추가 판단을 받는다.

무료 인스턴스는 유휴 시 정지하고 다시 시작하는 데 시간이 걸리며 재시작될 수 있다. 방은 현재 메모리 기반이어서 서버 재시작 시 사라진다. 개인 기록·할 일·타이머는 해당 배포 Origin의 기기 저장소에 남는다. 기존 개발 Origin 기록이 새 배포에 자동으로 옮겨지지 않으므로 필요한 경우 JSON 백업을 사용한다.

## 준비한 배포 설정

`deploy/render.preview.yaml`은 [공식 Blueprint 필드](https://render.com/docs/blueprint-spec)에 맞춘 검토용 설정이다. 파일이 존재하는 것만으로 배포하지 않으며 승인 전에는 Blueprint를 적용하지 않는다.

- Node.js 24.19.0, 싱가포르 단일 Free Web Service
- 빌드: `npm ci --include=dev && npm run build`
- 실행: `npm start`, Render가 제공하는 PORT에 바인딩
- 상태 확인: `/api/health`
- 자동 배포 끔. 새 커밋의 배포는 수동으로 검토 후 진행
- 외부 DB·디스크·음성·영상·분석 SDK 추가 없음

[Render Web Service](https://render.com/docs/web-services)는 공개 HTTPS와 [WebSocket](https://render.com/docs/websocket)을 지원한다. 설정 준비와 로컬 실행 검증은 실제 Render 배포 성공을 뜻하지 않는다. 로컬에서 PORT=3099로 프로덕션 명령을 실행해 HTML·health·실제 WebSocket 방 생성/퇴장 흐름은 통과했다. 플랫폼 계정의 접근 권한·로그 정책·무료 사용량은 배포 직전에 확인한다. 실제 공개 Origin과 서버 요청 Host가 다르면 정확한 공개 Origin만 ALLOWED_ORIGINS에 지정하며 Origin 검사를 완화하지 않는다.

## 승인 후 실행 순서

1. 계정·결제 조건·노출 범위와 승인한 소스 커밋 확인.
2. 자동 배포를 끈 단일 무료 서비스를 생성하고 HTTPS·health·Socket.IO 연결 확인.
3. 본인 휴대폰에서 처음 집중 → 할 일 시작 → 휴식 → 백업·복원 확인.
4. 다른 휴대폰과 초대 공유 → 입장 → 응원 → 일시 정지 → 화면 잠금/복귀 → 퇴장 확인.
5. iOS Safari/Android Chrome별 결과를 남기고 실패한 기능을 수정.
6. 시험 종료 후 서비스 중단. 정식 운영 전에는 연결 제한·운영 로그·접근 정책을 다시 검토.

## 실제 기기 체크리스트

- [ ] iOS Safari / Android Chrome 버전·기종 기록
- [ ] 같은 HTTPS URL에서 서로 다른 실제 참가자 2명 확인
- [ ] 공유 시트 성공·취소·링크 복사, 잘못된 코드 안내
- [ ] 할 일 시작·조기 종료·남은 목표 이어 하기·목표 달성
- [ ] 휴식이 공부 기록에 포함되지 않고 다음 집중을 자동 시작하지 않음
- [ ] 화면 잠금 1분·5분·30분 후 타이머와 참가 상태 복귀
- [ ] 네트워크 전환·비행기 모드·오프라인 퇴장 후 재입장 방지
- [ ] 기록·할 일 내보내기와 재복원, 플랫폼 서버 재시작과 개인 기록의 분리
- [ ] VoiceOver / TalkBack, 시스템 글자 확대, 바람 소리 사용자 조작
